# WTQ Build Track — Utility Bill Decoder (Design Spec)

Date: 2026-10-10
Competition: Women Tech Quest — Build Track
Model: Gemini 3.5 Flash-Lite (Google AI Studio, free tier) — configurable via `.env`

## 1. Goal

Build a CLI that reads Pakistani electricity bill images (K-Electric/KESC, LESCO,
IESCO) and generates two scored CSVs:

- **Level 1** (`output/level1.csv`, 10 rows): one JSON object per bill with
  provider, tariff, dates, meter readings, `charges[]`, `taxes[]`, totals,
  arrears, payable amounts. Values **as printed** (no recalculation); credits and
  subsidies negative; `null` for hidden/unreadable; **no personal identifiers**.
- **Level 2** (`output/level2.csv`, 120 rows): plain-English answers to the same
  12 questions about each bill, grounded only in that bill, numbers correct.

Deliverable ZIP (≤15 MB): `output/` CSVs + `source/` code + `README.md` +
`.env.example` (+ optional `demo/demo.mp4`). CSVs must be generated by code.
**Single submission — no re-upload.**

## 3. Architecture

Direct **vision LLM** (no OCR). Each bill image → Gemini with a strict prompt and
a JSON response schema.

```
source/
  run.py            # CLI: --bills <dir> --level1 <csv> --level2 <csv> --out <dir>
  wtq/
    config.py       # load MODEL_PROVIDER / MODEL_NAME / API_KEY from .env
    llm.py          # Gemini wrapper: image+prompt->JSON, retry/backoff, cache
    schema.py       # Level 1 JSON schema + required field list + context-pack schema
    normalize.py    # parse_amount, sign (CR->neg), dates ->YYYY-MM[-DD], null fill
    prompts.py      # extraction prompt, context-pack prompt, Level 2 answer prompt
    level1.py       # extract -> validate -> consistency check -> json column
    level2.py       # context pack + image + 12 Qs -> verified answers
    report.py       # output/_report.json + console summary
  tests/test_normalize.py
  requirements.txt
  README.md
  .env.example
output/   level1.csv, level2.csv, _report.json
cache/    raw LLM responses keyed by bill+prompt hash
```

## 4. Data flow

**Level 1** per bill:
1. provider hint from `bill_id` prefix (KESC→KE, LESCO, IESCO).
2. image + extraction prompt + response_schema → raw JSON.
3. `normalize.py`: strip commas/`Rs.`, `###CR`→negative, dates to required format,
   force every required field present (null if absent), drop any identifier that
   leaked in.
4. consistency check in code: `sum(charges)≈total_charges`,
   `total_charges+total_taxes≈current_bill`, `current_bill+arrears≈payable_within_due_date`
   (tolerance ±1). On mismatch → one targeted re-read of only the failing fields;
   keep printed values, record a confidence flag.
5. write one-line JSON into `level1.csv` (csv lib handles quoting).

**Level 2** per bill:
1. build a **context pack** once: Level 1 JSON + extracted 12-month usage history
   table + derived figures. Internal only — does not change `level1.csv`.
2. send context pack + image + the 12 question texts → model returns, per question:
   `answer_text`, optional `python_expression` + `numbers_used` for numeric claims.
3. for numeric answers, Python evaluates the expression and substitutes the verified
   value into the text. Non-numeric answers pass through.
4. write 12 rows into `level2.csv`.

## 5. Prompt rules encoded (from guide §5–6)

Extraction: extract as printed, never recalculate/round; amounts numeric PKR, no
commas/labels; credits & subsidies negative; one entry per printed line, skip
blank/zero lines, keep duplicates; classify charge-vs-tax by printed **section**
not name; subtotal null if not printed; dates to `YYYY-MM` / `YYYY-MM-DD`; `null`
for unavailable (never guess); **exclude** names/address/CNIC/account/reference/
consumer/meter numbers.

Answers: English only; do math via code; label estimates and show how computed;
state the interpretation if ambiguous; say the bill doesn't show a value instead of
guessing.

## 6. Reliability

- Per-bill `try/except`; failures still write a valid null-filled JSON / a
  "could not determine from the bill" answer → **no empty cells** (checklist).
- Retry with exponential backoff on HTTP 429; temp=0 for determinism.
- Call budget ~20 total (10 extract + 10 answer-batches) — well under free tier
  (15 req/min, 500/day). Response cache avoids re-spending on re-runs.

## 7. Validation

Run end-to-end on the 5 training bills now. Diff `KESC_0008` against the known
correct JSON (guide §5.7) to tune the prompt — the one labeled example. Eyeball
IESCO/LESCO. Unit-test `normalize.py`.

## 8. Out of scope (YAGNI)

Image deskew/preprocessing, multi-model consensus, web UI. CLI satisfies the spec
and suffices for the demo recording.
